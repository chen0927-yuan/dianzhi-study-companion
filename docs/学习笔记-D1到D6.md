## D1：git 保险 —— 敢改代码的前提

**为什么需要**：AI 改代码前先存档，改坏了 `一键还原`，才有试错的胆子。

**核心三命令**：
```bash
git init                    # 把文件夹变成仓库（只需一次）
git add <文件> / git add -A # 把改动放进"暂存区"
git commit -m "说明文字"    # 存档（生成一个版本号）
git log --oneline           # 看历史
```

**铁律**（V4.0 第 3 条）：
> 每次让 AI 改代码前，先 `git commit` 存档。

**安全关键**：`.gitignore` 文件排除敏感物，密钥永不入库：
```
.env                  # 环境变量（含 API Key）—— 绝不提交！
chroma_db/            # 向量库（可重建）
__pycache__/          # Python 缓存
*.log                 # 日志
```
验证方法：提交后 `git status` 干净 + 文件列表里无 `.env`。

**今日实战**：电智学伴 init + 2 次 commit → 推送 GitHub

## D2：看懂入口 —— 一个问题从发出到返回的 7 步

**阅读法（先总览后细节）**：main.py 从上到下 = 配置 → 逻辑 → 启动。

**请求链路**（勾选教材检索时）：
```
浏览器 → ① POST /chat-rag → FastAPI 收到
       → ② 交给 chat_rag(req) 函数
       → ③ retriever.retrieve() 去教材库找最相关 5 段（含页码+相似度）
       → ④ _make_rag_messages() 拼装：v6.0提示词+引用规则+教材片段
       → ⑤ Kimi 生成回答（看着片段写，标注（《教材名》第 X 页））
       → ⑥ _check_reply_pages() 检查回答里的页码是否都在检索结果里（防幻觉）
       → ⑦ 返回 JSON → 浏览器显示回答 + 引用卡片
```
普通模式（/chat）更短：跳过 ③④⑥。

**最重要的一课**：
> Kimi 只负责"写"，检查是**自己的代码**干的。
> 连 AI 的输出都要被程序检查 = V4.0「验证优先，默认怀疑」的落地。
> AI 生成 + 程序校验 = 双保险（答辩亮点！）

**认识代码**：`@app.post("/chat-rag")` = 接口门牌；`async def` = 处理函数；
`return {...}` = 上菜；`if __name__ == "__main__"` = 启动入口。

## D3：Python 四大语法（if / for / def / 嵌套）

### if —— 分岔路口
```python
if not API_KEY:              # 如果条件成立（没配 Key）
    return {"reply": "..."}  #   做这件事（缩进表示从属！）
# 条件后要冒号 :，下面缩进的代码才属于 if
```

### for —— 逐个过一遍
```python
for i, h in enumerate(hits, 1):   # 挨个拿，enumerate = 边数数边拿（1 起编号）
    lines.append(f"[片段{i}...]") # 循环体缩进
# 常见组合：for 里套 if（每项先判断再处理）
```

### def —— 造工具（黑箱流水线）
```python
def retrieve(self, query, top_k=None) -> list[dict]:
    # 输入 query → 干活 → return 成品
    return hits
```
**读函数三步**：① 看 def 行（输入）→ ② 看 return（输出）→ ③ 中间细节按需读。
名字前 `_` = 内部工具。用 = "调用"：`hits = retriever.retrieve(msg)`。

### 万能技巧：`or` 给默认值
```python
k = top_k or cfg.TOP_K
# 传了用你的（3），没传用默认（5）。None or 5 → 5
```

## D4：读懂核心 —— retrieve() 检索函数精读

**位置**：kb/retriever.py。**作用**：把问题变成向量 → 在教材库找语义最接近的段落。

```python
def retrieve(self, query, top_k=None) -> list[dict]:
    if self.count() == 0:        # ① 空库检查：没内容直接返回 []
        return []
    k = top_k or cfg.TOP_K       # ② 定数量：or 技巧
    res = self._col.query(       # ③ 真正搜索（调 Chroma 现成工具）
        query_embeddings=encode_query(query),  # bge 模型把中文变向量
        n_results=min(k, self.count()),
        include=["documents", "metadatas", "distances"],
    )
    hits = []
    for doc, meta, dist in zip(  # ④ zip 拉链式并排取 文本/页码/距离
        res["documents"][0], res["metadatas"][0], res["distances"][0]
    ):
        m = meta or {}
        hits.append({
            "text": doc,
            "title": m.get("title", ""),
            "pdf_page": m.get("pdf_page"),
            "printed_page": m.get("printed_page"),
            "score": round(1 - float(dist), 4),  # 距离→相似度
        })
    return hits                  # 交回带页码的清单
```

**关键认知**：
- **向量检索 ≠ 关键词搜索**：比"意思相近"，所以问"戴维南定理"能命中没出现这个词的表述
- `self._col.query(...)` = 调用别人写好的库（Chroma），不用自己实现搜索
- **分层/单一职责**：retrieve 只找材料；Kimi 才写答案——各管一段

**流程图**：问题 → 空库检查 → 定 k → 向量化搜索 → for 打包 → return 清单 → 交回 main.py

## D5：git 回滚 —— 三种后悔药（2026-09-06）

**核心口诀：看"坏提交出门了没"**

| 命令 | 后悔程度 | 适用场景 | 效果 |
|---|---|---|---|
| `git checkout -- <文件>` | 😅 轻度 | 文件改坏了**还没提交** | 文件回到上次存档的样子 |
| `git reset --hard <版本号>` | 😰 重度 | 提交错了**还没推送** | 时光倒流，历史干净（坏提交彻底消失） |
| `git revert <版本号>` | 🧯 安全 | 坏提交**已推送**且可能被别人拉过 | 追加一个反向提交抵消，不抹历史 |

**判断逻辑**：
1. 改坏未提交 → checkout（单文件还原）
2. 提交错未推送 → reset（抹掉历史）
3. 已推送/多人协作 → revert（安全补丁）

**辅助命令**：
```bash
git status          # 看哪些文件改了（M=修改）
git log --oneline   # 看历史找版本号
git reset --soft HEAD~1  # 撤销提交但保留文件改动（soft模式）
```

**为什么远程用 revert 不用 reset**：reset 抹历史会导致别人的仓库对不上；revert 是追加反向提交，大家平滑同步。

## D6：给开源项目加第一个前端功能 —— 知识库状态栏（2026-09-07）

**功能**：打开电智学伴页面，标题下方自动显示知识库状态（书名/页数/片段数）。
完成状态：已写入 frontend/index.html 并生效。

**改动只有 2 小块：**

**① HTML 加显示位置**（h1 标题下面）：
```html
<div id="kb-status" class="meta">📚 知识库加载中...</div>
```
- `id="kb-status"` = 给元素起名（门牌号），JS 靠它找到这个元素
- 初始文字“加载中...”，数据到了会被替换

**② JS 加取数逻辑**（页面打开自动执行一次）：
```javascript
function loadKbStatus() {
  fetch('/kb/status')                            // 向同源后端要数据（GET）
    .then(r => r.json())                         // JSON 文本 → JS 对象
    .then(data => {                              // data = {enabled, total_chunks, sources[]}
      const el = document.getElementById('kb-status');  // 找到占位牌
      if (!data.enabled || data.total_chunks === 0) {   // if：空库判断
        el.textContent = '📚 知识库为空...';
        return;
      }
      const names = (data.sources || [])
        .map(s => s.title + '（' + s.pages + '页/' + s.chunks + '段）')  // 遍历拼文字
        .join('、');
      el.textContent = '📚 知识库：' + names + ' ｜ 共 ' + data.total_chunks + ' 个片段';
    })
    .catch(() => { /* 出错提示 */ });
}
loadKbStatus();   // 页面一打开就执行
```

**核心认知**：
1. `fetch` = 浏览器里的“发请求”工具；这里走的是 D2 链路的**反向**（后端→浏览器，而不是浏览器问题→后端）
2. 看到 if / .map / 函数定义——全是 D3/D4 学过的概念的新用法，不是新知识
3. `.then` 链 = “先做这个，完成后再做下一个”（异步）
4. 前后端分离的雏形：后端只管给数据，前端负责显示

**验证方法**：刷新 http://localhost:8000 → 标题下方出现
“📚 知识库：test_textbook（6页/6段）｜ 共 6 个片段”
