## 三个"原来如此"

### 原来如此 1：git 不是网盘，是"时光机 + 后悔药"
以前以为存代码就是把文件放网盘。学了 D1/D5 才明白：git 每次 commit 都是给项目拍一张快照，改坏了随时能回去。
最关键是搞懂了三种后悔药的区别——**判断标准就看"坏提交出门了没"**：没提交用 `checkout` 还原单文件，提交了没推送用 `reset` 抹掉，推送了怕别人拉过就用 `revert` 打补丁。现在 AI 改代码前我会先 commit，再也不怕改坏了。

### 原来如此 2：AI 写的东西，不能直接信
我一直担心"不知道怎么判断 AI 对不对"。D2 学请求链路时发现，电智学伴自己就做了示范：Kimi 生成回答后，程序会有一个 `_check_reply_pages` 函数把回答里的页码和检索结果比对，**防 AI 编页码**。
原来"验证优先、默认怀疑"不是口号——连 Kimi 的输出都要被代码检查。以后我让 AI 写代码，也要先跑起来看结果对不对，而不是听它解释。

### 原来如此 3：网页是个"树"，前端没那么玄乎
D6 第一次亲手加功能（知识库状态栏）。原来页面上的每个标签都是 DOM 树上的一节，`getElementById` 就是按门牌号找到那个节点，找到后才能改它。
还懂了 `fetch` = 浏览器向后端要数据——之前以为前端后端是黑箱，现在知道它们就是互相发消息。**第一次看到自己加的功能在页面上跑起来**，感觉之前学的都串起来了。

## 关键编程语句速查（本周 D2–D6 实战中见过的重要语句）

> 不用背，当字典查：看到不认识就回来翻这页。

### Python（后端）

| 语句 | 作用 | 在哪见过 |
|---|---|---|
| `from X import Y` | 导入别人写好的工具/库 | main.py 开头 |
| `import os` | 引入系统工具（读环境变量用） | main.py 开头 |
| `os.getenv("KEY", "默认值")` | 读环境变量（.env 里的配置） | main.py 读 API Key |
| `def 函数名(参数):` | 定义一个函数（工具） | 所有 .py |
| `if 条件:` / `else:` | 条件判断（分岔路口） | 到处都是 |
| `for x in 集合:` | 循环（挨个处理） | retrieve() 打包结果 |
| `return 值` | 函数把结果交出去 | 所有函数末尾 |
| `X or Y` | X 为空用 Y（默认值技巧） | `top_k or cfg.TOP_K` |
| `[]` 空列表 / `.append(x)` | 建一个袋子 / 往里装东西 | retrieve() 收集命中 |
| `{}` 字典 | 带名字的箱子（键值对） | 返回给前端的 JSON |
| `"text": doc` | 字典里放一项（键: 值） | 片段打包 |
| `round(x, 4)` | 四舍五入保留小数 | 相似度格式化 |
| `try: ... except:` | 尝试执行，出错不崩（捕获异常） | 调用 Kimi 时 |
| `from kb.retriever import get_retriever` | 导入自己项目的模块 | main.py 路由里 |

### JavaScript（前端）

| 语句 | 作用 | 在哪见过 |
|---|---|---|
| `const x = ...` | 定义不可变的变量 | index.html 脚本 |
| `document.getElementById('id')` | 按 id 找到页面元素（门牌号） | D6 新功能 |
| `el.textContent = '...'` | 往元素里塞文字 | D6 知识库状态栏 |
| `fetch('/路径')` | 向后端要数据（发请求） | D6 调 /kb/status |
| `.then(r => r.json())` | 上一步完成后，把 JSON 转成对象 | D6 取数链 |
| `.then(data => {...})` | 拿到数据后处理（异步排队） | D6 取数链 |
| `.map(x => 加工x)` | 把列表每个元素加工一遍 | D6 拼书名列表 |
| `.join('、')` | 把列表用符号串成一个字符串 | D6 拼显示文字 |
| `JSON.stringify({...})` | JS 对象 → JSON 文本（发给后端） | 发问题时 |
| `??` | 左边是空就用右边（容错） | `data.tokens_used ?? '?'` |
| `async function` | 定义能等待异步操作的函数 | ask() 发问题 |

### Git（命令行）

| 命令 | 作用 |
|---|---|
| `git init` | 文件夹变成仓库（一次） |
| `git add -A` | 全部改动进暂存区 |
| `git commit -m "说明"` | 存档（拍快照） |
| `git log --oneline` | 看提交历史 |
| `git status` | 看当前改动 |
| `git checkout -- 文件` | 还原未提交的改动 |
| `git reset --hard 版本` | 时光倒流（抹历史） |
| `git revert 版本` | 安全撤回已推送的提交 |
| `git push origin main` | 传到 GitHub |
| `git pull` | 从 GitHub 拉最新 |

### 通用（前后端都要用）

| 概念 | 一句话 |
|---|---|
| JSON | 人和程序都能读的"数据文本格式"，前后端传数据都用它 |
| 缩进 | Python 里表示"这段属于上一行"，错了就崩 |
| 变量 | 给数据起个名字，`x = 5` 后 x 就是 5 |
| 函数 | 黑箱：给输入 → 干活 → 给输出 |
| 异步 | "先发请求，不等它，好了再回来处理"——`.then` 链 |

## 遇到的一个坎
第一次 push 失败（Connection was reset），一度以为代码丢了——后来发现是网络加速没开 + 本地 commit 本来就不会丢。**教训：commit 了就安全，push 失败只是"没传到云端"，随时能重试。**
